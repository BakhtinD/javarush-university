Уровень 19: Spring Boot Actuator и мониторинг приложений

Мы написали, протестировали и защитили наше приложение. Последний шаг перед отправкой в "реальный мир" — научиться за ним наблюдать. Развернутое приложение не должно быть "черным ящиком".

На этом уровне мы изучим Spring Boot Actuator — встроенный инструмент, который превращает ваше приложение в прозрачную и управляемую систему. Вы узнаете, как с помощью его эндпоинтов проверять "здоровье" приложения, анализировать метрики производительности и управлять конфигурацией на лету. Затем мы сделаем шаг к профессиональному мониторингу: интегрируем наше приложение с Prometheus для сбора метрик и Grafana для их визуализации. Вы также научитесь создавать собственные, бизнес-ориентированные метрики с помощью Micrometer.

Зачем нужен мониторинг?

Представьте, что ваше приложение развернуто на сервере. Как ответить на эти вопросы?

  • Оно вообще работает прямо сейчас?
  • Подключено ли оно к базе данных?
  • Почему оно стало медленно отвечать в последний час?
  • Сколько памяти оно потребляет?
  • Не заканчивается ли на диске место?

Без инструментов мониторинга ваше приложение — это "черный ящик". Вы узнаете о проблемах только тогда, когда позвонят разгневанные пользователи.

Что такое Spring Boot Actuator?

Spring Boot Actuator — это проект из экосистемы Spring, который предоставляет "production-ready" функциональность для ваших приложений.

Основная функциональность Actuator — это предоставление ряда HTTP-эндпоинтов (или JMX-бинов), которые раскрывают внутреннюю информацию о состоянии и работе приложения. Вам не нужно писать этот код с нуля. Actuator предоставляет готовые, стандартизированные инструменты для диагностики.

Подключение Actuator

Как и многое в Spring Boot, подключение Actuator — это вопрос добавления одной зависимости в pom.xml:

<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-actuator</artifactId>
</dependency>

После добавления этого стартера и перезапуска приложения Spring Boot автоматически сконфигурирует и предоставит доступ к базовым эндпоинтам.

По умолчанию, из соображений безопасности, большинство эндпоинтов доступны только через JMX. Чтобы сделать их доступными по HTTP, нужна дополнительная настройка.

Основные эндпоинты

Actuator предоставляет множество эндпоинтов. Вот четыре самых важных для начала:

  • /actuator/health - показывает обобщенную информацию о "здоровье" приложения.
  • /actuator/info - отображает произвольную информацию о приложении (например, версию сборки).
  • /actuator/metrics - позволяет посмотреть детальные метрики (CPU, память, потоки, HTTP-запросы и т.д.).
  • /actuator/env - показывает все переменные окружения и свойства конфигурации, с которыми запущено приложение.

Чтобы получить к ним доступ, их нужно "открыть" в application.yml.

Эндпоинт `/health`

Это самый важный эндпоинт. Системы оркестрации (Kubernetes, Docker Swarm) и балансировщики нагрузки постоянно опрашивают его, чтобы понять, жив ли данный экземпляр приложения.

Простой ответ:

{ "status": "UP" }

status: "DOWN" будет, если приложение не смогло запуститься или один из критических компонентов отказал.

Эндпоинт агрегирует статусы от нескольких HealthIndicator'ов. Spring Boot автоматически предоставляет индикаторы для баз данных, дискового пространства, RabbitMQ и т.д. Если, например, приложение не сможет подключиться к БД, общий статус станет DOWN.

Эндпоинт `/metrics`

Этот эндпоинт дает доступ к огромному количеству метрик производительности.

GET /actuator/metrics вернет список всех доступных метрик, например:

  • jvm.memory.used: использованная память.
  • system.cpu.usage: загрузка CPU.
  • http.server.requests: статистика по HTTP-запросам (количество, время ответа).
  • tomcat.threads.busy: количество занятых потоков в Tomcat.

Чтобы посмотреть значение конкретной метрики, нужно обратиться к GET /actuator/metrics/{metric.name}. Например, GET /actuator/metrics/jvm.memory.used.

Конфигурация Actuator

Управление эндпоинтами происходит в application.yml.

management:
  endpoints:
    web:
      exposure:
        # Указываем, какие эндпоинты открыть по HTTP
        # '*' - для всех, но это небезопасно!
        include: health, info, metrics, prometheus, loggers
        # exclude: env # Можно явно исключить опасные

  endpoint:
    health:
      # По умолчанию детали не показываются, только общий статус
      # "when_authorized" - показывать авторизованным пользователям
      # "always" - показывать всегда (не рекомендуется для продакшена)
      show-details: when_authorized

Это позволяет гибко настраивать, какая информация будет доступна по сети.

Безопасность Actuator

Некоторые эндпоинты Actuator могут раскрывать чувствительную информацию!

  • /env показывает все переменные окружения, включая пароли и ключи API.
  • /heapdump создает и отдает полный дамп памяти JVM.
  • /shutdown (по умолчанию выключен) позволяет выключить приложение через HTTP-запрос.

Никогда не открывайте эти эндпоинты для публичного доступа!

Если в проекте есть spring-boot-starter-security, Actuator автоматически интегрируется с ним. Вы можете настроить правила доступа к эндпоинтам так же, как и для обычных URL.

// В конфигурации SecurityFilterChain
http.authorizeHttpRequests(auth -> auth
    .requestMatchers("/actuator/health", "/actuator/info").permitAll() // Открыты для всех
    .requestMatchers("/actuator/**").hasRole("ADMIN") // Остальные - только для админов
    // ...
);

Кастомные индикаторы здоровья

Что если ваше приложение зависит от внешнего API, которое не имеет автоконфигурации от Spring Boot? Вы можете написать свой собственный HealthIndicator.

Это простой класс, реализующий интерфейс HealthIndicator.

@Component
public class ExternalApiServiceHealthIndicator implements HealthIndicator {

    private final ExternalApiClient apiClient; // Ваш клиент для внешнего API
    // ... конструктор ...

    @Override
    public Health health() {
        try {
            // Пытаемся выполнить тестовый запрос к внешнему сервису
            if (apiClient.isServiceAvailable()) {
                // Если все хорошо, возвращаем статус UP
                return Health.up().withDetail("message", "Service is available").build();
            } else {
                return Health.down().withDetail("message", "Service responded with an error").build();
            }
        } catch (Exception e) {
            // Если произошла ошибка, возвращаем DOWN
            return Health.down(e).withDetail("message", "Connection failed").build();
        }
    }
}

Теперь статус этого индикатора будет автоматически включен в общий ответ /actuator/health.

Интеграция с Prometheus

Проверять метрики вручную через /actuator/metrics неудобно. Нужна система, которая будет собирать эти данные постоянно, хранить их и позволять строить графики и алерты.

Prometheus — это open-source система мониторинга, которая стала стандартом в этой области.

Prometheus работает по Pull-модели: он не ждет, пока приложения пришлют ему данные. Вместо этого он сам периодически (например, каждые 15 секунд) обходит все настроенные эндпоинты (/actuator/prometheus) и "скрапит" (scrape) с них текущие значения метрик.

Эта диаграмма сравнивает две модели сбора метрик: Push, где приложения сами отправляют данные в систему мониторинга, и Pull, где система мониторинга (Prometheus) сама периодически опрашивает приложения.

Настройка экспорта в Prometheus

Интеграция с Prometheus в Spring Boot делается в два шага:

  1. Добавить зависимость: Она предоставит PrometheusMeterRegistry, который будет собирать метрики в формате, понятном для Prometheus. 
    <dependency>
    <groupId>io.micrometer</groupId>
    <artifactId>micrometer-registry-prometheus</artifactId>
</dependency>
  2. Открыть эндпоинт в application.yml: 
    management:
  endpoints:
    web:
      exposure:
        include: health, prometheus

После этого ваше приложение на эндпоинте /actuator/prometheus будет отдавать все свои метрики в текстовом формате, готовом для скрапинга Prometheus'ом.

Визуализация в Grafana

Сам по себе Prometheus — это в первую очередь база данных для метрик и система алертинга. У него есть простой UI для выполнения запросов, но для создания красивых и информативных дашбордов используется Grafana.

Grafana — это open-source платформа для визуализации и аналитики.

Стек мониторинга

graph TD A[Ваше Spring Boot приложение] -- предоставляет --> B["/actuator/prometheus"]; C[Prometheus Server] -- 1. Скрапит метрики (Pull) --> B; C -- 2. Хранит данные --> D[(Prometheus TSDB)]; E[Grafana] -- 3. Запрашивает данные для дашбордов --> C; F[Вы] -- 4. Смотрите дашборды --> E;

Grafana подключается к Prometheus как к источнику данных (DataSource) и позволяет строить графики, гистограммы и дашборды, отображающие состояние вашей системы в реальном времени.

Кастомные метрики с Micrometer

Actuator предоставляет множество системных метрик, но часто нам нужны метрики, специфичные для нашего бизнеса.

Spring Boot Actuator использует библиотеку Micrometer как фасад для работы с метриками. Micrometer позволяет писать код для сбора метрик один раз, а экспортировать их в разные системы (Prometheus, Datadog, InfluxDB и т.д.).

Основные типы метрик:

  • Counter: счетчик, который может только увеличиваться (например, orders_created_total).
  • Gauge: "датчик", показывающий текущее значение (queue_size).
  • Timer: измеряет длительность и количество событий (http_request_duration_seconds).
@Service
public class OrderService {
    private final Counter ordersCreatedCounter;

    // Внедряем MeterRegistry - фабрику для создания метрик
    public OrderService(MeterRegistry meterRegistry) {
        this.ordersCreatedCounter = meterRegistry.counter("orders.created.total", "region", "europe");
    }

    public void createOrder(Order order) {
        // ... бизнес-логика ...

        // Увеличиваем наш кастомный счетчик
        ordersCreatedCounter.increment();
    }
}

Логирование через Actuator

Эндпоинт /loggers — очень полезный инструмент для отладки на работающем приложении.

GET /actuator/loggers показывает все сконфигурированные логгеры в приложении и их текущие уровни (INFO, DEBUG, ERROR и т.д.).

Самая мощная возможность — изменять уровень логирования на лету с помощью POST-запроса, без перезапуска приложения.

POST /actuator/loggers/com.example.service.PaymentService Тело запроса: { "configuredLevel": "DEBUG" }

Это позволяет временно включить детальное логирование для проблемного компонента прямо на продакшене, чтобы найти причину ошибки, а затем вернуть уровень обратно на INFO.
